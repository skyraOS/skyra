# Places

## Primitives, Places, and Tools

Three layers, clear ownership:

- **Being** owns primitives — look, listen, speak, engage. Its senses. Travel with it across worlds.
- **Place** owns tools — what's available there. The plugin boundary.
- **Engage** is the bridge — the being's primitive that crosses into a place and gets access to its tools.

A tool is a Reality. It has a name and content. The content describes how to use it — natural language, read by the LLM like anything else. No special mechanism. No adapter. No tool schema. The same interface that works everywhere: name + content.

A place is a Reality. Its Relationships map contains tools. The being engages the place, the tools activate based on what the Relation is carrying, the content surfaces, the being reads it and acts.

Skills emerge from whatever the substrate needs them to emerge from. A being that uses a tool enough builds weight structure around that experience. We don't define what a skill is. We don't get in the way of that.

## Places as Plugins

Places are the extensible surface. Open source contributors build places. A forge has a hammer and an anvil. A library has search and read. A terminal has bash. Each place is structured however the contributor wants — they don't need to follow the DNA pattern internally. The runtime doesn't care what's inside. It cares that when a being engages the place, tools come back on the Relation. The contract is the boundary, not the implementation.

A place implements Reality. That's the entire contract. How the internals work — whether it uses Skyra's DNA, a flat lookup, a database, an external API — is up to whoever builds it. The runtime calls `Realize()` and reads what comes back.

## Places as Binding Realities

Places scale in both directions. The place gives the being access to tools — that's outward. But being in a place also raises the weights of the being's memories that were formed in that place — that's inward.

A being engages the forge. Every memory the being made while previously engaged with the forge carries a binding field to it. Those memories activate. The being remembers how to use the hammer because it's standing in front of the anvil. Not because it searched. Because the place raised the weights.

This is context-dependent memory — Tulving's encoding specificity. Memories are easier to retrieve when the retrieval context matches the encoding context. The place IS the retrieval context. Same mechanism as thread — thread binds co-occurring messages, the place binds co-occurring experience. No separate mechanism needed. The binding field is already there.
