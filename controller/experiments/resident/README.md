# Resident connection custody experiment

Implements the first transport experiment from
spec 18. This is a test
harness, not the production resident-target mode or a migrated Codex adapter.
The existing Codex host is still in use.

Run on macOS, outside an enclosing sandbox that prevents `sandbox-exec`:

```sh
go test -count=1 -v ./controller/experiments/resident
```

The tests re-execute their own binary as separate launcher, custodian, fake
provider, operation, and tool processes. Provider and operation/tool processes
run under profiles generated by the existing `boundary.Render`. No model,
credentials, network, or real Codex process is used.

## What passes

```text
launch resident → exchange → isolated tool → park → resume → exchange → stop
```

- The launcher exits before the first exchange. Each succeeding custodian exits
  after an acknowledged SCM_RIGHTS handoff using `controller/runtime/handshake`.
- An experimental manifest distinguishes frame directories from connections,
  with owner and incarnation identity. Old senders close their resource copies
  after acknowledgment. The resident stays the same process throughout.
- The fake provider writes three lines together. One is consumed; the others
  remain in the connection through tool execution and parking, then are returned
  by a later worker. A partial line interrupted by a deadline is returned and
  supplied as the next worker's prefix.
- An unrelated sandboxed tool inherits neither the connection nor frame
  directories. It cannot read the protected floor or launch a nested
  `sandbox-exec`. Carrying a resource in trusted custody does not grant it to
  every target.
- Stale incarnation and foreign-owner requests are refused before a worker
  receives the connection. The resident remains usable afterward.
- A stop worker calls `shutdown(SHUT_WR)` on its granted endpoint. This signals
  EOF despite the custodian retaining another copy; the worker drains the fake
  provider's farewell and observes peer EOF. The custodian's retained endpoint
  can no longer write.
- Closing the last endpoint without shutdown also makes the fake provider exit.
- Workers deliberately die after writing and after reading. The custodian
  reports delivery/read uncertainty rather than resubmitting. In the read case,
  the consumed response is unavailable: this is an explicit failure boundary.
- The main sequence commits invocation operands before execution and returned
  observations before the next operation. Existing intake, narrow, resolve, and
  replay functions re-derive its 24-record lineage. Time is an observation in
  the recorded return, not a clock read during replay.

## Findings for production implementation

**Stop is a resource operation.** Closing a child's copy cannot give the peer
EOF while a runtime custodian retains its copy. Socket shutdown is viable for
this stream socketpair experiment and affects all duplicate endpoints. A
production stop must then remove the dead resource from custody and report
termination accurately. Peer EOF alone is not proof that an arbitrary process
has exited; the experiment separately checks fake-provider exit on last-close.

**Reads have an uncertainty window too.** Kernel buffering protects unread
data while the endpoint survives. It does not protect bytes consumed by a worker
that dies before committing its return. Do not promise lossless crash recovery
or exactly-once effects from this design. A successful write is reported as
`written`, not as provider acknowledgment.

**Explicit grants require close-on-exec.** The first isolation test found an
unintended raw socketpair descriptor inherited by a tool. `handshake.Pair` and
received handshake/park descriptors now set close-on-exec; explicitly passing a
descriptor through `ExtraFiles` still works. The experiment exercises the
handshake behavior across actual process exits.

## Scope and next work

The parking helper models an ingress custodian, holding the experimental bundle
until an outside resume signal. It uses the real handshake transport, but is
**not** the production `park.Frame` wire format, browser host, or `skyra resume`.
The journal uses the real machine and replay functions; the harness is not the
production `instance.Drive` loop, and it does not rerun adapter policy in replay.

Production integration still needs typed resource metadata through `Drive`,
handoff, frame pop, parking, and resume; owner-scoped cleanup; resident start
observations; operation contracts; and the ephemeral adapter. Connection grants
in this harness are experimental manifest checks, not yet Boundary fields or
per-invocation authority narrowing. The current renderer's broad read/Mach
permissions remain; this experiment does not implement spec 17's restrictions.

The harness uses a single serialized custody chain and does not prove fan-out or
exclusive use against a faulty holder that duplicates a descriptor. It also
does not prove end-to-end recovery after a custody holder dies.

Real Codex EOF behavior, per-process startup/memory cost, auth isolation, and
the stronger app-server sandbox from spec 17 remain unverified. These tests
prove the fake provider's transport mechanics, not those provider-specific
assumptions.
